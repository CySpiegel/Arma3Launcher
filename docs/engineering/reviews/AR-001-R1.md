## Blocking findings

### AR1-B1 — Game installation readiness undefined

Revision 1 lines 99–118 define game manifest discovery and Workshop readiness but
do not map game appmanifest update/error/completion evidence into Play readiness.
Lines 127–134 allow DLC selection based on package presence. Lines 149–151 require
revalidation without defining underlying game/DLC readiness. The installation
report includes StateFlags, UpdateResult and download/staging progress. An
implementation could launch partly updated game/DLC files and still follow the
written discovery rules.

Required: distinguish bundle presence from game readiness; block recognized
pending/update/error/incomplete states and apply game state to game-relative
DLC. Define unknown/unreadable and manual-folder behavior. Re-read readiness
metadata before Play. Test ready, updating, malformed/missing manifest and manual
folder cases. Full file-integrity verification is not required.

### AR1-B2 — Multiple installations and duplicate items lack resolution

Revision 1 lines 81–95 model one game and stable Workshop IDs; lines 99–118 scan
all libraries; lines 161–163 deduplicate by ID without deciding between distinct
physical copies/manifest states. Filesystem iteration could choose silently.

Required: honor a valid explicit game selection; define multiple-auto-candidate
behavior and never silently fall back after an explicit selection disappears.
Retain duplicate Workshop provenance and define availability/precedence or an
ambiguity blocker. Fixtures must cover two installations and duplicate IDs with
different readiness. A warning plus deterministic precedence is sufficient.

## Nonblocking findings requiring disposition

- AR1-N1: Normalize advanced argument names case-insensitively, including `=`
  forms after whitespace treatment. Test `-MOD`, `-ServerMod`, `-PAR`, and mixed
  typed flags. This clarifies the existing conflict-rejection rule.
- AR1-N2: Game-level C:-paths with spaces and absolute DLC paths remain unproved.
  A4 requires recorded mode, exact process/target, argv and positive in-game
  evidence for representative addon and optional DLC. Exercise both advertised
  modes where available and explicitly mark any unverified mode. Missing loading
  evidence is incomplete, not a pass.
- AR1-N3: A game can start externally between preflight and LaunchServices
  handoff. With no new instance, an existing process may be returned without new
  arguments. Inspect returned bundle URL, test already-running behavior, keep
  status honest, and do not permit duplicate processes as a workaround.
- AR1-N4: README says Git is uninitialized and HANDOFF calls the completed
  investigator active. Reconcile factual snapshots before coding dispatch.

native UI/Foundation split, explicit bundle URLs, shell-free argv, read-only

resolve findings. Distribution, remote integration and untested platform
