## Gate execution semantics for the repair

During an active construction attempt, no submitted candidate exists yet. Verify
the current task, packet, attempt and architecture inputs, run the full checks,
then generate the source manifest. Clearly label this construction verification.
For a submitted attempt, additionally require its bound candidate manifest/hash
to match the actual complete source inventory before running the same gate.
Root records submission before its independent gate. Never compare a repair's
changed source with a prior attempt's candidate or overwrite that prior evidence.
This distinction avoids circular candidate generation without weakening the
submitted-candidate acceptance check.
